# مصفوفة دعم DXF — محرر مهندس المجلس

**الحالة:** قارئ/كاتب ASCII R2000 مستقل، موصول الآن بواجهة محرر 2D وRoom. هذه المصفوفة تفرق بين ما يقرأه محرك DXF وما يستطيع نموذج التطبيق تخزينه. لا تعني عبارة «يمكن الاستيراد» حفظ الملف بلا فقد.

**القاعدة:** قبل الإضافة تعرض الواجهة وحدة القياس والتحذيرات والعناصر التي لن تدخل نموذج الرسم. يُحفظ النص الأصلي للملف في مساحة التطبيق الخاصة ويُسجل مساره وملخص التحويل للمشروع. لا يستبدل التصدير الأصل. تصدير الرسم الحالي ينتج تمثيلًا محدودًا فقط، وليس نسخة مطابقة من ملف CAD المستورد.

## مصفوفة المحرك ونموذج التطبيق

| العنصر | قارئ/كاتب DXF | نموذج CAD داخل التطبيق | النتيجة في واجهة الاستيراد/التصدير |
|---|---|---|---|
| LINE | قراءة/كتابة | LINE | يُستورد ويُصدّر؛ تقلب الواجهة محور Y وتحوّل وحدة الملف إلى متر عند الاستيراد. |
| LWPOLYLINE / POLYLINE 2D | قراءة/كتابة بالمحرك | لا يوجد نوع polyline | يظهر ضمن غير المضاف؛ يحتفظ المستخدم بالأصل. RECT المرسوم داخل التطبيق يصدّر كـclosed LWPOLYLINE. |
| CIRCLE | قراءة/كتابة | CIRCLE (صندوق/قطر) | يستورد/يصدّر كدائرة بعد تحويل المركز ونصف القطر. |
| ARC | قراءة/كتابة بالمحرك | لا يوجد نوع قوس | لا يدخل نموذج CAD؛ يظهر ضمن العناصر المتروكة. |
| TEXT | قراءة/كتابة بالمحرك | TEXT موضع/حجم/محتوى فقط | يستورد النص وموضعه وحجمه؛ دوران النص يسقط مع تنبيه صريح. التصدير لا يحفظ خصائص نمط النص أو محاذاته. |
| MTEXT, DIMENSION, INSERT/BLOCK, HATCH, SPLINE, ELLIPSE, POINT وغيرها | غير مدعوم بالمحرك | لا يوجد | تعدّ وتظهر ضمن التحذيرات؛ الكتل لا تفكك إلى عناصر. |
| Z والإحداثيات ثلاثية الأبعاد | يقبل عناصر 2D المختبرة مع عدّ Z المهمل | 2D فقط | يهمل Z ويعرض عدد العناصر المتأثرة. |
| الطبقات | يحفظ المحرك أسماء الطبقات | طبقات Room | تنشأ الطبقات الناقصة عند الاستيراد؛ لا تنتقل ألوان CAD أو أنواع الخط/السماكة. أسماء الطبقات غير ASCII تُحوّل في التصدير إلى `LAYER_nn` ويعرض التطبيق ذلك. |

## الوحدات والملف

- وحدات `$INSUNITS` المعروفة: inch وfoot وmillimeter وcentimeter وmeter. تحول الإحداثيات إلى المتر في قاعدة التطبيق.
- الوحدة غير المعروفة أو UNITLESS تتطلب اختيار المستخدم من واجهة الفحص؛ لا تستخرج كميات من الملف.
- محور Y في DXF عكسي عن محور الشاشة؛ يحول المحول الإحداثيات في الاتجاهين.
- يرفض الملف الفارغ أو المقطوع/التالف بنيويًا برسالة؛ حد الإدخال في الواجهة 10 MiB.
- يُحفظ الأصل بايتًا ببايت داخل `filesDir/dxf-originals/<projectId>/` وتُحفظ بيانات الاستيراد والتحذيرات في جدول `dxf_import_records`. الملفات ذات المحارف الخام غير ASCII تُرفض للتحليل مع إبقاء الملف لدى المستخدم كما هو؛ لا يعاد ترميز الأصل.
- التصدير R2000 ASCII لعناصر نموذج التطبيق المعروفة: LINE وRECT وCIRCLE وTEXT. أي عنصر آخر أو اسم طبقة غير ASCII يعلن عنه بعد التصدير. لا يدعي هذا توافقًا شاملًا مع كل إصدار أو خاصية في DXF/DWG.

## ما لم يثبت بعد

- لم يختبر التدفق المتصل على هاتف فعلي أو مع ملفات AutoCAD/LibreCAD حقيقية، كبيرة، أو من جميع الإصدارات.
- لم تجر مقارنة بصرية لتطابق الوحدات، مواضع النص، المحور والطبقات بين قارئ CAD مستقل والتطبيق.
- لا يوجد محرر ARC/POLYLINE أو DWG مباشر، ولا تحول DWG داخل التطبيق.
- لا يوجد ربط موثوق لعناصر الرسم بمواد/كميات؛ لا تستخرج كميات تلقائيًا قبل تأكيد الوحدات والمقياس وإغلاق المساحات.
- اختبارات القارئ/الكاتب والواجهة الجديدة تحتاج أن تجتاز تشغيل GitHub Actions للالتزام الحالي.

## الأدلة المرجعية

- ملفات اختبار DXF المولدة ومصفوفة المحرك الأصلية محفوظة تحت `app/src/test/resources/dxf/` و`tools/dxf/`.
- اختبارات `DxfReaderTest` و`DxfWriterTest` و`verify_export.py` تخص محرك النص المستقل؛ لا تثبت سلامة النقل إلى نموذج CAD على هاتف حتى تنفذ اختبارات الربط والجهاز.
