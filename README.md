# مهندس المجلس | Majlis Engineer

تطبيق Android أصلي لإدارة مشاريع المجالس وأعمال البناء والتشطيبات، بواجهة عربية RTL، وحفظ محلي يعمل دون اتصال. يبنى عبر GitHub Actions لأن بيئة التطوير المتاحة للمستخدم هاتف.

## الوظائف المنفذة حاليًا
- لوحة متابعة ومشاريع متعددة؛ يمكن تعديل بيانات العميل والموقع والنوع والحالة وتاريخ البدء وموعد التسليم المتوقع.
- معاينة ميدانية قابلة للإضافة والتعديل، مع تحقق من الأبعاد والفتحات وحساب مساحة الأرضيات والجدران الصافية.
- جدول كميات قابل للإضافة والتعديل والحذف، بسعر بيع وتكاليف مواد وعمالة اختيارية لكل بند.
- محرك تكلفة مستقل عن الواجهة وCAD: كمية صافية، هدر، تقريب لوحدة الشراء، تكلفة المواد والعمالة، مبلغ البيع والربح والهامش؛ مبالغ OMR إلى ثلاث خانات عشرية.
- إعدادات نقل ومصاريف إضافية وخصومات محفوظة لكل مشروع؛ تقرير وواجهة ملخص مالي يوضحان أن الربح غير محدد عند نقص التكلفة أو تعذر حساب بند.
- ترحيلات Room حتى 7→8 تضيف حقول التكلفة والتواريخ والموردين والأسعار والمخزون وإعدادات التكلفة والتصميم وسجل DXF الأصلي وعناصر MEP، دون إسقاط الجداول السابقة.
- مهام التنفيذ وسجل الملاحظات الفنية حسب التخصص.
- كتالوج مواد محلي مع وحدة وماركة وسعر أساسي مستقل، ودليل موردين وبيانات تواصل وعروض أسعار مرتبطة بالمادة ومرتبة حسب وحدة البيع ثم السعر.
- سجل مواد ومخزون لكل مشروع: الكمية المطلوبة والمستخدمة والمتبقية أو العجز، سعر مشروع اختياري وتكلفة تقديرية؛ وحدة السجل تحفظ عند الإضافة.
- تقرير مشروع PDF.
- مساحة الرسم MEP ثلاثية الأبعاد صارت أول تبويب في ملف المشروع وتبدأ تلقائيًا عند فتحه؛ تعرض الغرفة المقاسة وطبقات السباكة والكهرباء، وتتيح اختيار خدمة/قطعة ثم وضع نقاط المسار بلمس الأرضية أو الجدار مع معاينة وتراجع وشبكة 5 سم وارتفاع قابل للضبط للنقر على الأرض. هذه الإضافة الجديدة تنتظر إعادة بناء CI واختبار اللمس فعليًا على الهاتف.
- طبقات مستقلة للماء البارد/الحار والصرف والطور R/Y/B والمحايد/الحماية؛ مسارات الأنابيب/القنوات/الكابلات، الكوع، T، المحبس، الإنارة، المفتاح والمقبس محفوظة محليًا ويمكن تحديدها وإعادة رسمها أو حذفها.
- شاشتا CAD وInterior Design ثنائيتا الأبعاد وشاشة استيراد DXF محفوظة في المستودع لكن مخفية من تنقل المشروع بناء على طلب المستخدم؛ ليست هي مساحة الرسم المطلوبة في هذه المرحلة.
- قاعدة بيانات Room محلية مع migrations للحفاظ على بيانات الإصدارات السابقة.
- Gradle Wrapper رسمي مثبت على Gradle 8.9 مع بصمة SHA-256؛ CI يستخدم `./gradlew` نفسه المستخدم محليًا.

## الحدود الحالية
- حساب الربح يُعرض فقط للبنود التي أدخل لها المستخدم سعر مادة أو عمالة؛ لا يفترض النظام تكلفة صفرية للبنود غير المسعرة.
- تم إخفاء واجهات CAD والتصميم الداخلي 2D مؤقتًا؛ البيانات والشيفرة السابقة باقية في المستودع. الأولوية لمساحة 3D باللمس، وليست لتطوير أدوات خط/دائرة/نص.
- استيراد DXF ليس تحريرًا كاملًا: نموذج التطبيق لا يخزن القوس أو الخط المتعدد، وتُظهر الواجهة هذا قبل الإدراج وتحتفظ بالأصل. دورانات النص وبعض الخصائص وZ لا تنتقل كما هي؛ راجع `docs/technical-tests/dxf-support-matrix.md`. يلزم تشغيل CI واختبار ملفات حقيقية على الهاتف وفي CAD مستقل؛ DWG-to-DXF وربط الرسم آليًا بالحصر غير متاحين.
- أسعار المواد وعروض الموردين ومخزون المشروع محفوظة محليًا؛ لا يوجد بعد استيراد Excel أو مزامنة بين الأجهزة أو ربط تلقائي للمخزون ببنود BOQ.
- اجتاز نموذج MEP الأولي في PR #5 اختباراته وبناء APK؛ لكن رسم المسار المباشر باللمس أضيف لاحقًا ويحتاج إعادة CI واختبار الهاتف. هندسة الأذرع للكوع/T تمثيلية، فتحات الأبواب والنوافذ لا تُطرح من الجدران، ولا يوجد بعد ربط تلقائي بجدول BOQ أو مهام وجدول 4D أو محاكاة ضغط/سلامة. ألوان الكهرباء إيضاحية ويجب الرجوع للمعيار العماني الحالي ومختص.
- المزامنة السحابية غير مكتملة. التصميم الداخلي الحالي معاينة 2D، وليس محرر أثاث/مواد حرًا أو مشهد 3D.
- تصدير Excel وعروض الأسعار الرسمية وسجل القياسات والتغييرات المتقدم غير مكتملة.
- APK الحالي debug للتجربة؛ نجاح البناء لا يثبت التثبيت أو الاستخدام على هاتف فعلي. لا يُعاد استخدام مفتاح debug للتوقيع الإنتاجي.
- المخرجات الهندسية مساعدة وتحتاج مراجعة مهندس مختص قبل التنفيذ.

## البناء والتحقق
الإصدار الجاري 0.10.0 (versionCode 10). يتطلب البناء JDK 17 وAndroid SDK. من جذر المستودع شغّل `./gradlew testDebugUnitTest` للاختبارات و`./gradlew assembleDebug` لبناء APK في `app/build/outputs/apk/debug/app-debug.apk`. GitHub Actions يشغّل الأوامر نفسها عبر Gradle Wrapper، ويتحقق من التوقيع، ثم يرفع ملف APK كأثر workflow. اختبار الهاتف الفعلي منفصل عن نجاح البناء. راجع `TODO.md` و`docs/technical-tests/early-technical-risk-validation.md` لمعرفة ما اجتاز التحقق وما ينتظر اختبار الجهاز.
